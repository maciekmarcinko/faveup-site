# FaveUp – marketing site (faveup.app)

Rebuild of the Figma Make site at `www.faveup.app` as plain static files, with the detailed presentation replaced by the 12-slide deck from `FaveUp - Prezentacja.pdf`.

- `site/index.html` – landing with the **Dla Biznesu** / **Dla Użytkowników** views. The old hash routes keep working: `#/business-view`, `#/users-view`, and `#/prezentacja` redirects to the deck.
- `site/prezentacja/` – the deck. Desktop shows one slide at a time on a scaled 16:9 canvas (arrows, keyboard, swipe, `#3` deep links). Phones and portrait tablets get the same slides as a scrolling page. "Pobierz PDF" downloads the original PDF.
- The FaveUp film plays inside the iPhone in the business hero and on slide 2. The hero phone starts on the sample concert notification (Klub Nuta), plays the film in place, and returns to the notification when it ends (`site/js/phone-player.js`).
- PL is the default, written in the HTML. Each English page is its own static file generated by `npm run build`: `site/en/index.html` from `site/index.html` + `i18n/landing.en.mjs`, and `site/en/prezentacja/index.html` from `site/prezentacja/index.html` + `i18n/deck.en.mjs`. Every `data-i18n` / `data-i18n-attr` key must exist and every English key must be used, or the build fails. Never edit `site/en/` by hand; `npm run dev` and `npm run deploy` rebuild it, and deploy refuses to run while the rebuilt files are uncommitted. The PL/EN switches are links between the two pages (`site/js/lang-links.js`); a remembered English choice and old `?lang=en` links send the Polish pages to their English versions.
- `site/google2c6b51a2208c8e3d.html` verifies the site in Google Search Console (`https://www.faveup.app/` property, usabilitysolutions.contact@gmail.com). Keep it, or verification is lost.
- SEO: each language has its own title, description, canonical, Open Graph tags and JSON-LD, both pages list each other with `hreflang`, and `site/robots.txt` points at `site/sitemap.xml`. Keyword targets are listed under "Keywords" below.
- Waitlist forms post to the same Formspree form the Figma site used (`xwlezeap`), now with `source` (business-view / users-view) and `language` fields.
- Google Analytics 4 (property "FaveUp", Measurement ID `G-CYXPNEX0P0`) runs behind a cookie banner: `site/js/consent.js`, loaded with an absolute `/js/consent.js` path by every public page, including the QR signup pages built in `../QRs`. It uses Consent Mode v2: analytics cookies stay off until the visitor clicks Accept, and ad signals are never granted. The choice is stored in `localStorage` (`faveup-consent`), and any element with `data-cookie-settings` reopens the banner. The tag only loads on `www.faveup.app`, so local previews never count as visits. The privacy policy it links to is `site/privacy/` (English: `/en/privacy/`, built from `i18n/privacy.en.mjs`); update it when the site starts collecting anything new. Keep the admin panel without the script.

## Run locally

```bash
npm run dev
```

Opens `http://localhost:5180/`. No install step: the site has no dependencies.

## Deploy

Live on GitHub Pages (`clint123-ops/faveup-site`), served from the `gh-pages` branch, which holds only the contents of `site/`. After committing to `main`:

```bash
npm run deploy
```

That replaces `gh-pages` with the current `site/` from `main` (the branch is only ever a copy, so it is force-pushed), and Pages republishes within a minute or two. `site/CNAME` keeps the custom domain set on every deploy. Custom domain: `www.faveup.app`. Namecheap DNS has `A @` → 185.199.108–111.153 and `CNAME www` → `clint123-ops.github.io`, and GitHub redirects `faveup.app` to `www`.

Any other static host works too, as long as it answers HTTP Range requests for the `.mp4` (Safari will not play the film otherwise).
